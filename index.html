Case studies

CS-01 Broken Access Control — IDOR lab

objective

Verify whether object-level authorization was enforced on a multi-user application.

approach

Mapped endpoints referencing identifiers; created two test accounts; replayed requests in Repeater swapping IDs; compared responses to detect missing ownership checks.

finding

GET /api/orders/{id} returned other users' order data with a 200 — the server authenticated the request but did not verify ownership.

impact

Horizontal privilege escalation: any authenticated user could read other users' orders and personal data.

remediation

Server-side ownership check on every object access, non-guessable identifiers where feasible, and access-control regression tests.

Performed in a controlled lab environment — no production systems touched.

CS-02 Authentication & Session Weaknesses lab

objective

Review the session lifecycle: login, reset, storage and logout.

approach

Tested brute-force protection, analyzed reset-token entropy, inspected cookie flags, and verified server-side invalidation after logout.

finding

Reset tokens were predictable; sessions were not invalidated server-side after logout; some cookies lacked Secure/HttpOnly.

impact

Account-takeover paths: a leaked or reused token stayed valid indefinitely.

remediation

Cryptographically random reset tokens, server-side session revocation, cookie hardening, rate limiting on sensitive flows.

Performed in a controlled lab environment — no production systems touched.
