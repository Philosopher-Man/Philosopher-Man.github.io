Case studies

        
      


      

        
          CS-01
          Broken Access Control — IDOR
          lab
          
        
        

          

            
objective
Prove that object-level authorization was missing on a multi-user application.

            
approach
Mapped every endpoint referencing identifiers; created two test accounts; replayed requests in Repeater swapping IDs; used Autorize to detect missing server-side ownership checks.

            
finding
GET /api/orders/{id} returned other users' order data with a 200 — the server authenticated the request but never verified ownership.

            
impact
Full horizontal privilege escalation: any authenticated user could read any other user's orders and personal data.

            
remediation
Server-side ownership check on every object access, non-guessable identifiers where feasible, and access-control regression tests in CI.

          

          
Performed in a controlled lab environment — no production systems touched.

        

      


      

        
          CS-02
          Authentication & Session Weaknesses
          lab
          
        
        

          

            
objective
Audit the complete session lifecycle: login, reset, storage and logout.

            
approach
Tested brute-force protection, analyzed reset-token entropy, inspected cookie flags, and verified server-side invalidation after logout in Burp.

            
finding
Reset tokens were predictable; sessions were not invalidated server-side after logout; cookies lacked Secure/HttpOnly on some paths.

            
impact
Realistic account-takeover paths: a leaked or reused token stayed valid indefinitely.

            
remediation
Cryptographically random reset tokens, server-side session revocation, cookie hardening, and rate limiting on sensitive flows.

          

          
Performed in a controlled lab environment — no production systems touched.
